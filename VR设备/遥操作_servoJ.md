# Vision Pro 遥操 AR5 + 因时灵巧手

左手控制机械臂末端,右手捏合当离合,五指独立跟踪。

---

## 一、怎么用

```bash
conda activate dexgraspvla
cd ~/yuhang_workspace/数据_硬件/灵巧手遥操/VR设备
python avp_servoj_teleop.py <头显IP> --planner spline --lag-ms 50 \
    --rot-mode beside --ws-max-z 0.60 \
    --w-psi 0.5 --max-step-rad 0.015
```

头显 IP 从 Tracking Streamer 界面上读,每次可能变。

**四个参数都不是默认值,都不能省**:

| 参数 | 没有它会怎样 |
|---|---|
| `--rot-mode beside` | 默认 `roll` 把手的倾斜整份丢掉,高度封顶 495mm |
| `--ws-max-z 0.60` | 默认 0.47 = 470mm,**比姿态锁定的 495mm 天花板还低**,前两个参数一分钱换不到 |
| `--w-psi 0.5` | 默认 0.15,肘游移明显 |
| `--max-step-rad 0.015` | 默认 0.03,最坏情况臂以 215°/s 扫过去;改完是 107°/s |

### 按键

| 键 | 作用 |
|---|---|
| **ENTER** | 挂/摘离合。打印 `[离合] 挂上` 才算生效 |
| 右手捏合 | 保持捏住臂才动,松开即停(dead-man) |
| `h` | 停下并关节回位 |
| `q` | 退出 |

状态行最左边三种:`未挂离合`(回车没进来,多半终端没焦点)、`等右手捏合`、`接合`。
**只有 `接合` 才是真的在跟。**

### 跑完先看这四个数

| 数 | 基线 | 不对劲的表现 |
|---|---|---|
| `ik 失败` | **0** | 涨 = 目标超出可达范围 |
| `残差` | **1.9mm** | 劣化 = 臂跟不上 |
| `解→解 最大` | — | **>50° 就是出事了**,臂会大幅扫动 |
| SNAP 行的 `ψ` | ±60° 内 | 跑出去 = 位形在累积漂移,见第七节 |

基线来自 2026-10-10 14:09 那次 275 秒的正式任务
(`logs/servoj_20261010_140947.log`):ik 失败 0/25589、残差 1.9mm、
逆解中位 3.46ms p95 5.96ms、步长限幅 1.4%、手 20.4Hz 零错。

## 二、这套系统在做什么

每 8 毫秒一个循环,做五件事:

```
读头显手腕位姿 → 滤波 → 算臂的目标位姿 → 逆解成关节角 → 发给控制器
```

控制器收到关节角后,自己把 8 毫秒的间隔插补成 1 毫秒的运动。
端到端延迟约 72 毫秒,其中 50 毫秒是我们主动加的延迟缓冲(换顺滑)。

### 为什么用 servoJ

控制器每毫秒需要一个关节角指令。Python 做不到每毫秒准时发一次,
晚几毫秒控制器就判通信丢包。珞石 SDK 给了三条路,只有一条适合遥操:

| 接口 | 语义 | 遥操延迟 |
|---|---|---|
| MoveL | 每个点是一个**任务**,必须走完,撤不回 | 240~500 ms,手越快越差 |
| RT 笛卡尔 | 每毫秒一个位姿 | 这台 AR5 上收指令不动 |
| **servoJ** | 每 8 毫秒一个**关节角目标**,新的盖掉旧的 | **24 ms** |

关键区别是队列。MoveL 发进去的点排队等着被执行,手停了臂还要把队列走完,
延迟等于队列深度乘每点执行时间。servoJ 没有队列,发一个盖一个,控制器永远追最新那个。

代价是 servoJ 收关节角不收位姿,**逆解要我们自己做**。

## 三、每一步的原理

### 1. 读头显

Tracking Streamer 给左手手腕的 4×4 位姿矩阵,大约每秒 60 帧。

### 2. 滤波

头显位姿自带抖动,不滤的话噪声原样变成关节指令。三级:

- **卡尔曼**(匀速模型):按运动学模型压噪声,顺带估出手速,后面帧间预测要用。
- **One-Euro**:速度自适应低通。手停住时压得死,快速挥动时几乎不引入延迟。
  普通一阶低通做不到这一点,压得住抖就一定发糊。
- **逆解前再滤一级**:前两级在头显原始位姿上,但之后帧间预测和坐标映射会重新引入噪声,
  这一级直接滤送进逆解的目标。姿态是取旋转矩阵前两列滤完再 Gram-Schmidt 重建 ——
  九个元素分别滤出来不是正交阵,送进逆解是个带缩放的伪旋转。

### 3. 算目标位姿

接合那一刻记下手的位姿和臂末端的位姿作为基准。之后:

```
目标位置 = 基准位置 + 坐标变换 × (手的位移) × 缩放
```

坐标变换是 `--yaw` 和 `--mirror` 合成的。头显系是 X 右、Y 前、Z 上;
臂基座系是 X 前、Y 左、Z 上。两者差一个绕 Z 的旋转,现场用 `probe_axes.py` 测一次。

**基准是接合时重新记的**,所以可以"划船":摘离合、手挪回舒服的位置、再接合,
位移从新基准继续累加。手的行程不够时就这么走。

**帧间预测**:头显 60 赫兹而控制周期 125 赫兹,中间两个周期若沿用同一个陈旧目标,
后面的速度估计就按错误的间隔算。用卡尔曼估的手速把位置外推到当前时刻。

目标最后钳进工作空间盒。盒子的边角臂到不了,所以各面向内收一点。

### 4. 逆解

AR5 是 7 轴,末端位姿只定 6 个量,多出来的一个自由度是**臂角**,
也就是肘绕"肩到腕"这条连线转多少。同一个末端位姿有无数组关节角。

求解分两层:

**闭式解**(`ar5_poe_ik.py`):把臂角当已知量代进去,剩下 6 轴用旋量法加
Paden-Kahan 子问题闭式求出,没有迭代。扫一遍臂角就得到一批候选解。1.9 毫秒。
**所有候选都是解析精确解**(实测 ik 残差 0.0mm)。

**选解层**(`ar5_ik_select.py`):求解器只负责给出全部解,挑哪个是策略问题。三道关:

1. **跳变门**:扔掉离上一帧超过 0.25 弧度(14.3°)的候选。同一构型里也有差半个臂角的远解。
2. **构型筛选**:只留和接合时同构型的。用三个比特描述臂处在哪个姿势里 ——
   手腕正反、肘朝哪边、肩在前还是在后,组合成八种。同一个末端位姿,不同构型是完全不同的
   臂型,它们之间没法连续过渡,中间要经过奇异。不筛的话会不知不觉跨过构型边界,
   臂突然换个姿势。
3. **代价排序**:连续性、关节限位余量、近奇异、臂角偏离锚定值,加权取最小。

合计 3.5 毫秒(p95 6.0 毫秒),周期 8 毫秒。

### 5. 插值与发送

逆解只在头显有新帧时更新(约 16.7 毫秒一次),而 servoJ 每 8 毫秒要一个点。
中间的点靠插值填。

**延迟缓冲**是这一版顺滑的关键。把逆解结果连时间戳存进缓冲区,
输出的是 50 毫秒之前那一刻的值。因为落后了,输出点的两侧都有真实数据,
可以做**内插**而不是外推,切线用中心差分。外推只能猜下一个目标在哪,
目标一抖速度估计就抖,样条跟着过冲。

发送是一个一个发,servoJ 没有批量接口。

> **注意**:`DelayedSpline` 的 `--max-vel` / `--max-acc` **只夹 Catmull-Rom 的切线、
> 只记统计,不限速**。输出 `q_new` 从不被它们约束。这条路上**唯一真正限速的是
> `--max-step-rad`**(0.015 rad / 8ms = 107°/s)。退出时打印的"超过 --max-vel N 周期"
> 是在报超了,不是报被夹住了。

## 四、姿态模式:为什么要 beside

### 高度天花板的真身是腕部限位

末端位姿一旦定死,**腕部两个关节的角度就被唯一确定了**,没得选。7 轴里多出来的那个
自由度是臂角,它改的是 J1/J3,帮不了腕部。

从 home(末端 251mm)往上,保持工具朝向不变,全周扫臂角取腕部最宽松的解:

| 臂z | 腕部占 ±47° 限位 |
|---|---|
| 451mm | 79% |
| 491mm | 96% |
| 511mm | **无解** |

**这就是 495mm 天花板。** 顶死之后症状是逆解无解 → 臂停住 → 手继续走 →
下一帧要跳得更远,和跳变门那条雪崩链是一个形状。

### 唯一的解法:少要一点姿态

工具歪一点,腕部就松一截(表里是腕部占限位 %,"—"=不可达):

| 臂z | 0°倾斜 | 10° | 15° | 20° | 30° |
|---|---|---|---|---|---|
| 491mm | 96 | 79 | 71 | 61 | 46 |
| 511mm | — | 87 | 75 | 70 | 53 |
| 551mm | — | — | 94 | 83 | 70 |
| 591mm | — | — | — | — | 84 |

### 三种模式

把手的转动拆成两份:**绕工具轴的拧转**(不改工具朝向,不花腕部行程)和
**倾斜**(把工具轴扳歪,高度全靠它换)。三种模式的区别只在倾斜那份留多少:

| 模式 | 拧转 | 倾斜 | 高度 | 工具朝向 |
|---|---|---|---|---|
| `roll` | 全留 | **全丢** | 封顶 495mm | 恒定,是数学不变量 |
| `full` | 全留 | **全留** | 590mm | 随手歪,臂也可能顶腕部限位 |
| `beside` | 全留 | **按腕部余量滑** | 590mm | 够得着时跟手,顶不住才摆正 |

`beside` 维护一个系数 `s`:`s=1` 就是 `full`,`s=0` 就是 `roll`。
每帧看上一帧解出来的腕部占限位:

- 超过 `--tilt-use-hi`(0.88) → `s` 往下滑,把倾斜还回去换高度
- 低于 `--tilt-use-lo`(0.80) → `s` 往回爬,工具自动摆正
- 速率 `--tilt-rate`(0.7/s),两阈值之间是滞回带,接合时 `s` 复位成 1

**离合关着时三种模式都一样**,选解层根本不被调用。

### 阀门防的是什么:臂突然不跟手

和高度无关。`full` 下手的姿态是**硬要求**,逆解必须精确满足;手一转到需要腕部超过
±47° 的角度就**无解** → 臂停住 → 手还在动 → 下一帧要跳得更远 → 跳变门拒收 →
雪崩到完全不动。阀门在腕部用到 88% 时把倾斜还回去一点,让解重新存在。

**哪些方向危险**(工具初始朝向是前下 48°,基座系 X前 Y左 Z上):

| 工具尖端倒向 | 结果 |
|---|---|
| 前上 / 前左上 / 前右上 | 省腕部,`full` 也没事 |
| 右 | 临界 |
| **后右下 / 后下 / 后左下 / 左** | **吃腕部,`full` 会停** |

规律:**把工具往臂根方向收、或者往下压 = 吃腕部;往前推、往上抬 = 省腕部。**

举手够高处时手腕是自然前倾上抬的,正好落在省腕部那三格 —— 所以**阀门真正该出力的
时刻是在中低高度转手腕调工具角度时**,不是在举高时。

### 两个容易误解的点

**倾斜来自你的手,臂不会自己歪。** 手端平着往上抬,`beside` 没有倾斜可跟,
照样封顶 495mm。它适合的是"抬高跨障碍/转场、到位后再摆正"这种用法 ——
抬手时手腕自然前倾,臂跟着;放平手,工具自己摆正回去。

**`beside` 是保护,不是增高器。** 高度是 `full` 式跟手拿到的,
`beside` 只负责在腕部要顶死时把倾斜还回去,让臂不至于停住。

## 五、参数

### 必须自己定的

| 参数 | 怎么来的 | 不对会怎样 |
|---|---|---|
| `<头显IP>` | Tracking Streamer 界面上读,每次可能变 | 连不上,卡在等头显 |
| `--yaw` | 现场用 `probe_axes.py` 测,推导值 `-90` | 前后左右整体转 90 度,姿态也一起错 |

### servoJ 三个参数

| 参数 | 默认 | 原理 |
|---|---|---|
| `--period` | 0.008 | 我们对控制器的承诺:多久给一个点。**滞后约等于三倍周期**,实测 8ms→24ms、20ms→60ms。太小伺服报错,太大判通信丢包 |
| `--lookahead` | 0.008 | 发送时刻会抖,设了这个值控制器就按固定间隔算速度,抹平抖动 |
| `--kp` | 1.0 | 位置反馈增益。振荡调小,滞后大调大 |

主循环周期、插值周期、这个承诺周期必须是同一个值,否则控制器算出的速度是错的。

### 延迟与顺滑

| 参数 | 默认 | 原理 |
|---|---|---|
| `--lag-ms` | 50 | **顺滑度的主旋钮**。落后这么多才能拿到输出点两侧的真实数据做内插。**至少 35**(要覆盖两个头显帧间隔),低于这个值右边没点会退化成保持不动。50 是拐点 |
| `--target-cutoff` | 4.0 | 逆解前那级滤波的截止频率。对 0.5 赫兹的手部动作,2Hz 滞后 30ms、4Hz 滞后 20ms、6Hz 滞后 15ms |
| `--lp-cutoff` | 3.0 | 头显位姿那级滤波。三处滤波的滞后是叠加的,要调先调 `--target-cutoff` |

### 速度与安全

| 参数 | 默认 / 推荐 | 原理 |
|---|---|---|
| `--max-vel` / `--max-acc` | 1.2 / 8.0 | **不限速,只记统计**(见第三节的注) |
| `--max-step-rad` | 0.03 / **0.015** | **这条路上唯一真正限速的闸**。0.015 rad/8ms = 107°/s。它不拒绝大跳,只把跳摊成多帧扫过去。实测正常跟手每帧只要 p50 0.14° / p90 0.49°,离 0.86° 上限有 1.8 倍余量,所以收紧几乎零代价 |
| `--ws-margin-mm` | 60 | 工作空间盒 x/y 各面向内收。够不到臂根附近时调小它 |
| `--ws-margin-z-mm` | 20 | z 方向收得少,收多了臂"下不去" |
| `--ws-max-z` | 0.47 / **0.60** | 末端高度上限。**默认值比 495mm 天花板还低**,想抬高必须改 |

### 手感与姿态

| 参数 | 默认 / 推荐 | 原理 |
|---|---|---|
| `--scale` | 0.4 | 手动 1 米末端动 0.4 米。定它看退出统计的 `[手速] p99` 和 `[离合周期] 中位位移`:盒子用不到一半而重捏很频繁 = scale 太小。**按 p99 定,别按峰值** |
| `--rot-mode` | roll / **beside** | 见第四节 |
| `--tilt-use-hi/lo` | 0.88 / 0.80 | beside 阀门的开关阈值,中间是滞回带 |
| `--tilt-rate` | 0.7 | 阀门的变化速率(每秒)。快动作下腕部会先冲过阈值阀门才跟上,可以试 1.5 |
| `--w-psi` | 0.15 / **0.5** | 选解代价里臂角偏离的权重。大则肘钉死,小则更跟手但肘会慢慢游移 |
| `--ik-max-jump` | 0.25 rad | 逆解跳变门(14.3°) |

### 调参顺序

1. **抖** → `--target-cutoff` 降到 2 或 3;还抖 → `--lag-ms` 加到 80。
2. **滞后** → `--lag-ms` 降到 40(不能低于 35);还慢 → `--target-cutoff` 升到 6。
3. **肘乱动** → `--w-psi` 升到 0.5。
4. **够不到,老是撞工作空间** → 先看 `[工作空间]` 三轴用了几成,
   用不到一半就是 `--scale` 的问题,不是盒子。
5. **抬不上去** → `--rot-mode beside --ws-max-z 0.60`。

每次只动一个,跑完对比退出统计。

## 六、日志怎么看

跑起来就有运行日志写在 `logs/servoj_<时间>.log`,每秒一行快照 + 退出统计。

### 退出统计

```
选解: 调用 N  无解 N  平均候选 N 个/次  臂角漂移 X°  构型滤掉 N 个候选，被迫换构型 N 次
      跳变门: 拒掉 N 个候选，放开 M 次（门限 14.3°）  臂角单帧最大 Y°
      最大跨越: 解→指令 X°（含臂被限幅拖后的量）   解→解 Z°（求解器自己的不连续）
[跳变]   解→指令 最大 X° (t=..s，以 ..°/s 扫需 N 帧)   解→解 最大 Z°
[步长需求] 正常跟手 N 帧: p50 .. p90 .. p99 .. p99.9 ..   跳支恢复中 M 帧: 中位 .. 最大 ..
[手速]   接合中 p50 .. p90 .. p99 .. 最大 .. mm/s  → 末端(×scale) p99 .. mm/s
         速度预算: p99 需 ..°/帧，占步长上限 ..° 的 ..%
[工作空间] 盒(含留边) vs 实际用到,三轴各自的百分比
[离合周期] N 个，每个末端净位移 中位 ..mm 最大 ..mm
[高度链路峰值] 手Δz .. -> 目标z .. -> 钳后 .. -> 臂z .. mm
[beside] 腕部占限位峰值 ..%   倾斜跟随最低 ..
手: 跟踪 N 次 出错 N 次 实测 ..Hz    (低于臂的一半会直接告警)
```

### SNAP 行(每秒一行)

`ψ=±..° 跨越=..° 解跨=..° 门放开=N 臂xy=(x,y) 腕部=xx% 倾斜跟随=x.xx`
外加高度链路 `手Δz / 目标z / 钳后 / 臂z / ik残差` 和 `q` / `qgoal`。

### 读法

- **`解跨` 才是求解器的不连续**。`跨越`(解→指令)会被"臂落后"放大,
  实测同一时刻两者能差一倍(15.45° vs 7.90°),拿它判跳支会误判。
  **解→指令大而解→解小 = 臂被限幅拖在后面;两个都大 = 求解器真的跳了支。**
- `解跨` >5° = 真跳支,末端会甩几十毫米;<2° = 正常跟手。
- `[步长需求]` 把"正常跟手"和"跳支恢复中"分开统计 —— 拿混在一起的 p99 去定
  `--max-step-rad` 等于白定,跳支被摊开的那十几帧会把分位数顶上去。
- `[工作空间]` 三轴百分比 + `[离合周期]` 中位位移,一起回答「`--scale` 够不够」。
- `beside` 的两个:腕部峰值没到 `--tilt-use-hi`、或 `倾斜跟随最低` 还是 1.00
  → 阀门全程没触发,这次跑下来等于 `full`;掉到 0.00 → 一路退化成 `roll`。
- 高度链路从左往右读:**手Δz 不够 = 手没抬够**(划船多接合几次);
  **目标z 够高而钳后低 = 被盒子钳住**;**钳后够高而臂z 不够 = 逆解或规划器没跟上**。

## 七、出问题看哪里

| 症状 | 原因 |
|---|---|
| 连不上头显,errno 11 | Tracking Streamer 退到后台或头显休眠。切回前台,确认界面上的 IP |
| 按了回车臂还是不动 | 状态行左边:`未挂离合`=回车没进来(终端没焦点);`等右手捏合`=右手没捏住 |
| `ec=-3 急停按钮被按下` | 急停自锁,**断电重启不会让它弹起来**,只能手拧。`powerState` 报 `off` 看不出来,`ec=-3` 才是判据 |
| `电机上不了电` | 上一次退出 RT 模式后掉电。程序会重试 6 次;还不行等 40 秒再跑 |
| 运动被静默拒绝(`reachTarget=False` 但 `ec=0`) | 关节在软限位外,用 `softlimit_rescue.py`。这种情况 `home_arm.py` 会**误报「完成」** |
| 臂"抬不上去",停在半空 | 腕部顶到 ±47° 限位,见第四节。`--rot-mode beside --ws-max-z 0.60` |
| 臂"下不去" | `--ws-margin-z-mm` 设太大 |
| 够不到臂根附近 | `--ws-margin-mm` 设太大(默认 60) |
| 臂姿势越来越别扭,像朝后折着够前面 | 冗余自由度累积漂移。**摘离合跑 `home_arm.py` 重置**,重新捏合没用(接合会把当前位形重新锚定) |
| 臂突然大幅扫动一两秒 | 上一条的脱困动作。退出统计里 `解→解 最大` 会很大 |
| 逆解失败计数在涨 | 目标超出可达范围。手回到工作空间中间重新捏合 |
| 前后左右整体转了 90 度 | `--yaw` 不对,跑 `probe_axes.py` 定值 |
| 左右反了但前后是对的 | 这是反射不是旋转,yaw 修不了,加 `--mirror lr` |
| 正解自检差超过 5mm | 本地运动学和控制器对不上,程序会自己停。查 `ar5_dh.json` |
| 手一个字节都不回 | 手的控制循环半死。**拔手自己的 24V 电源**,等 5 秒再上,不是拔 USB。先用 `test_fingers.py` 单独验证 |
| 手的串口找不到 | 拔插后设备号会变。用 by-id 路径 |

状态行里的 `R捏` 是**米**(捏合距离),小于 0.020 才算捏住。
和 `--pinch-gate` 无关 —— 那个参数走的是另一条路。

## 八、文件

| 文件 | 作用 |
|---|---|
| `avp_servoj_teleop.py` | **主程序**,遥操就跑这一个 |
| `ar5_poe_ik.py` | 旋量法闭式逆解 |
| `ar5_ik_select.py` | 选解层:跳变门、构型筛选、代价排序 |
| `ar5_sew.py` | 构型三比特判别、立体投影臂角 |
| `hand_retarget.py` | 25 关节手骨架 → 手的 6 维 |
| `inspire_hand6.py` | 灵巧手驱动 |
| `home_arm.py` | 单独把臂送回起始姿态(非 RT,排队式 MoveAbsJ,从任何位形都出得来) |
| `softlimit_rescue.py` | 关节跑到软限位外时的救援(临时关软限位,收尾必恢复) |
| `probe_axes.py` | 定 `--yaw` / `--mirror`,不碰臂 |
| `test_fingers.py` | 逐根手指张合,只碰手 |
| `probe_servoj.py` | 量 servoJ 的滞后和稳定性,不连头显 |
| `test_changes.py` | 离线回归,上真机前先跑 |

对照用的其他方案:`avp_movel_teleop.py` 走控制器 MoveL,
`avp_arm_teleop.py --arm-backend rt` 走本地 1kHz 关节流。两者的延迟都明显更大,留着做对比。
